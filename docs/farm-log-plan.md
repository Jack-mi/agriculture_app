# 农事日志与多地块成本分摊改造计划

## Summary

把现有「记事」升级为覆盖作物全生育周期的「农事日志」，并让一笔开销可以按种植季分摊到多个地块。同步更新产品文档和小程序实现，不新增依赖、不新建云端集合，继续复用现有本地 Storage + CloudBase 同步架构。

## 数据与接口变更

- `logs` 记录扩展为：
  - `growth`：作物生长发育情况，文字记录。
  - `pest`：病虫害情况，文字记录。
  - `machine`：机械/机手信息，如“汤日刚的高精度播种机”。
  - `areaMu`：本次作业完成面积。
  - `materials`：农资/投入品使用列表，每项为 `{type, name, rate, unit}`；`type` 固定为「种子 / 农药 / 化肥 / 其他」，单位支持「斤/亩、公斤/亩、株/亩、ml/亩、g/亩」。
  - 保留现有 `ops`、`text`、`moisture`；旧记录的 `fertName/fertRate` 自动映射为一条化肥使用记录，原字段保留作兼容。
- `costs` 记录改为分摊模型：
  - 新增 `allocations: [{seasonId, amount}]`。
  - `amount` 保存分摊金额合计；`seasonId` 仅作为旧数据兼容字段，不再作为统计依据。
  - 旧成本记录读取时自动归一化为 `[{seasonId, amount}]`。
- `weather` 记录新增：
  - `wind`：当日最大风速，单位 m/s，来源 Open-Meteo `wind_speed_10m_max`。
  - 保留 `t`、`p`、`src`、`updatedAt`；旧天气记录缺少 `wind` 时显示「—」。
- 云端接口：
  - `weatherBackfill` 与 `weatherDaily` 返回并写入 `{t, p, wind}`。
  - 不新增集合；`allocations`、`materials` 等作为既有 `costs` / `logs` 文档的内嵌字段同步。

## Implementation Changes

- 文档口径：
  - 更新 `PRD.md`、`MVP-PRD.md`、`miniprogram/README.md`。
  - 明确农事日志四类内容：环境信息、农情信息、机械化耕作与田间管理、农资购买与使用。
  - 明确「全生育周期天天记录」的实现口径：每个种植季生成连续日历，天气自动填充，农情/作业/农资按日补充，缺记日期可见可补记。
  - 明确一笔开销只录一次，通过多个种植季金额分摊计入各地块，不允许全额重复计入。
- 农事日志页面：
  - 增加作物生长、病虫害、机械/机手、作业面积、农资使用明细输入区。
  - 默认操作类型补充「播种、收获、病虫害观察」。
  - 日期选择限制在当前种植季起止范围内；已收获季节可补记到收获日。
- 种植季日志列表：
  - 从播种日到收获日/今天生成连续日期底卡，倒序展示。
  - 每天显示日期、第几天、气温、降雨、风力；无天气时显示待补。
  - 没有人工记录的日期显示「本日未记录」，并提供按该日期补记的入口。
  - 日志卡片展示生长、病虫害、机械、面积、农资使用和关联花费。
- 记账页面：
  - 金额按选中的种植季逐行录入，自动合计总金额。
  - 可添加多个地块/种植季分摊；至少一个分摊金额必须大于 0。
  - 本季流水显示分摊到本季的金额；多地块分摊的账目加「共用」标识。
- 统计与删除：
  - 成本汇总、每亩成本、每斤成本均按本季分摊金额计算。
  - 删除某个种植季时，只移除该季分摊；若账目仍分摊给其他季则保留，否则删除整笔账。
  - 删除地块时同样保留仍分摊给其他地块的成本。
- 天气：
  - 天气详情和手工修正弹层增加风力。
  - 手工修正仍优先于 API 数据。
  - 统计页展示逐日风力与全周期最大风力，不累计风力。
- 云函数：
  - 更新两份 Open-Meteo 拉取代码，加入 `wind_speed_10m_max`。
  - 部署 `weatherBackfill` 和 `weatherDaily` 后，线上天气才实际返回风力；未部署前只保证本地代码兼容。

## Test Plan

- 本地逻辑测试：
  - 旧单季成本自动迁移，且本季统计金额不变。
  - 一笔 4800 元成本分摊为 2000 / 2800 后，两季分别只计入各自金额，总计为 4800。
  - 删除其中一个分摊季后，另一季仍能看到剩余分摊金额。
  - 全生育周期日历包含每一天，跨年冬小麦不断档；无记录日期显示为未记录。
  - 旧施肥记录能显示为化肥使用明细。
  - 手工修正风力后不被 API 覆盖。
- 静态检查：
  - 对修改过的 JS 文件运行 `node --check`。
  - 用 Node 内置测试跑成本分摊、日志日历、旧数据迁移的最小用例。
- 小程序验证：
  - 使用微信开发者工具编译并打开项目，确认无编译错误。
  - 手工走通用户示例：7 月 2 日玉米机械播种，记录机手、机械、120 亩、4200 株/亩、种肥 80 斤/亩、40 元/亩费用，并把费用分摊到两个种植季。
  - 验证已收获季节、跨年季节、无天气数据日期和共用成本显示。

## Assumptions

- 「天天记录」不强制每天生成一条人工记录；产品保证连续日历、天气自动记录和缺记可见。
- 成本分摊目标是「种植季」而不是裸地块；未开季地块需要先创建种植季才能参与成本分摊。
- 风力采用最大风速 m/s，不做风力等级换算。
- 不新增提醒、消息推送、图表或复杂权限能力。
- 不新增第三方依赖；继续使用 Open-Meteo 和现有 CloudBase 同步机制。
