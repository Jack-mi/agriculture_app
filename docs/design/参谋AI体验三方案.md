# 参谋 AI 体验三方案 · 设计稿

> 来源：Ant Design X 调研（2026-10-06）。结论：Ant X 是纯 React 库，无法直接接入小程序，但其 RICH 范式（Role / Intention / Conversation / Hybrid）与组件语义可照搬到我们的手写实现。本文档覆盖三个可落地方案。
>
> 两个关键现状（决定了这三个方案的成本）：
> 1. `miniprogram/utils/chat.js` 里已有 `chipsFor(ctx)` 上下文提示函数，**写完没接线**，聊天页从未渲染它。
> 2. 云函数 `advisorAgent` 的回包里已带 `toolTrace`（格式：总管步骤为 `ask_bookkeeper`，子代理步骤为 `记账:query_costs`），**客户端在 `askAgent` 里直接丢弃**。
>
> 因此方案一、二都**不需要改云函数**，只动小程序端。

---

## 方案一：空会话提示集（Prompts / 意图预期引导）

### 目标
农户打开参谋页不知道能问什么、怎么说。Ant X 规范里这叫"意图预期"缺失，是 AI 对话产品最普遍的断点。用可点的提示把"能干什么"直接摆在开场。

### 交互设计

两层结构，职责分开：

**A. 开场提示集（仅空会话出现一次）**
- 位置：欢迎语气泡下方，竖排 3~4 条大按钮（整行可点，右箭头示意）。
- 行为：点一下**直接发送**（不填输入框，农户少一步操作），发送后整个提示集消失（该消息标记 `promptsDone`）。
- 时机：只有 `setHello()` 路径（无本地/云端历史）才渲染；有历史会话拉回时不出现。

**B. 常驻快捷条（复用现有 `chipsFor`）**
- 位置：输入栏上方一行横向滚动小 chips。
- 行为：点击直接发送。用户发出任意一条消息后收起（避免和对话抢注意力），下轮回复后不再出现，保持收起，简单。
- 文案就是现有 `chipsFor(ctx)` 的三条，按上下文换。

**提示集文案（按进入上下文三选一）**

| 上下文 | 提示集 |
|---|---|
| 无上下文 | 「接下来地里该干啥」「今天干了活，帮我记一笔」「这季到现在花了多少钱」「提醒我后天去河边地打药」 |
| 带地块（seasonId） | 「这块地接下来该干啥」「这季花了多少」「上回打药是哪天」「帮我记一笔今天的活」 |
| 带任务（taskId） | 「这条任务往后推两天」「已经干完了」「这条不做了，以后也别推」 |

文案原则：第一句必须是"收益型"问题（该干啥/花多少），让农户先尝到问答的甜头，再发现能记账记事。

### 改动点
- `miniprogram/pages/chat/chat.js`：`setHello()` 里给 hello 消息挂 `prompts: [...]`（按 ctx 选表）；新增 `tapPrompt` 方法 = `send(text)` + 清掉 prompts；渲染常驻 chips 行 + `tapChip`。
- `miniprogram/pages/chat/chat.wxml`：hello 气泡下加 prompts 列表；输入栏上方加 chips 行。
- `miniprogram/pages/chat/chat.wxss`：两个样式块，大按钮复用现有 `.act` 卡片的圆角/底色语言。
- `utils/chat.js`：`chipsFor` 文案微调即可，函数不动。
- 云函数：无改动。

### 边界情况
- 语音入口农户从来不打字：提示集与语音无冲突，点提示等价于说了一句。
- 历史会话云端拉回（`chatlog.pull` 成功）时不显示提示集，避免老用户被打扰。
- 提示点击后 `persist()` 照常走，刷新后提示集不再出现（用户消息已存在）。

### 验收标准（模拟器）
1. 清空对话进聊天页 → 欢迎语 + 4 条提示；点「这季花了多少钱」→ 直接发问并正常回包。
2. 带 taskId 从任务页进 → 提示集换成任务版三条。
3. 发问后退出重进 → 提示集不再出现。
4. 无网络时点提示 → 走现有失败话术，不崩。

### 工作量
约 0.5 天，纯前端，可随任意版本上。

## 方案二：思维链步骤化（通俗版 ThoughtChain）

### 目标
后端本来就是总管 + 记账/记事/农事三子代理的多智能体结构，但农户只看到"想了 N 秒"。把 `toolTrace` 翻译成人话步骤展示出来，让农户看到"参谋真去翻了账本、查了资料"，增强信任，也让结果更可解释。

### 关键约束（2026-10-07 已升级）
~~`advisorAgent` 是非流式的，等待过程中拿不到中间步骤，只在回复到达后展示。~~
真机反馈"等待几十秒一直是静态"后升级为**真·实时步骤**：`advisorAgent` 每次工具调用把 toolTrace 快照写入 `advisorProgress` 集合（按 reqId 标记），`advisorChat{action:'progress'}` 提供只读轮询口，chat 页思考期间每 2s 轮询并用同一套 parseTrace 实时渲染（当前步高亮），回包即停。等待态从"静态一句话"变成"步骤一条条冒出来"。

### 交互设计
- 回复气泡内，现有"已思考（展开）"一行改为两行结构：
  - 第一行：「参谋干了这些」（默认折叠），展开是步骤列表。
  - 第二行：保留现有"已思考"原文（reasoning），藏进步骤列表底部"看原始思考"二级入口——普通农户不需要，但排查问题时能看。
- 步骤列表渲染：每条一行，小圆点 + 一句话；超过 6 条时中间折叠为「等 N 步」。

**步骤文案映射表**（`toolTrace` 条目 → 人话）：

| trace 条目 | 展示文案 |
|---|---|
| `ask_bookkeeper` | 叫来记账参谋 |
| `ask_logger` | 叫来记事参谋 |
| `ask_agronomist` | 叫来农事参谋 |
| `*:query_costs` / `*:query_summary` | 翻了账本 |
| `*:query_debts` | 查了欠款 |
| `*:query_accounts` | 看了账户余额 |
| `*:query_stock` | 查了库存 |
| `*:query_budget` | 对了预算 |
| `*:query_recurring` / `*:query_templates` | 查了周期账/常用账 |
| `*:query_logs` | 翻了农事记录 |
| `*:query_tasks` | 看了待办 |
| `*:query_plots` / `*:query_seasons` | 看了地块和种植季 |
| `*:query_weather` / `*:weather_forecast` | 看了天气 |
| `*:kb_search` | 查了农技资料 |
| `*:pesticide_check` | 核对了打药安全 |
| `*:memory_search` | 翻了记住的事 |
| `*:draft_*` | 拟好了一张确认卡（合并为一条，不逐个列） |
| `*:memory_save` / `*:memory_forget` | 记下了/忘掉了一条 |

处理规则（前端 `parseTrace`）：
1. 连续相同的步骤合并成「翻了 3 次账本」。
2. `draft_*` 全部折叠成一条，反正卡片本身会展示。
3. 空 trace（纯闲聊直接答）→ 不渲染"参谋干了这些"，避免"啥也没干"的尴尬。

### 改动点
- `miniprogram/utils/chat.js`：`askAgent` 里 `out.trace = parseTrace(res.toolTrace)`；新增 `parseTrace`（映射表 + 合并规则，纯函数，约 60 行）。
- `miniprogram/pages/chat/chat.js`：`reply()` 把 `r.trace` 挂到消息上；加 `toggleSteps`。
- `chat.wxml` / `chat.wxss`：步骤列表区块，样式对齐现有 `.reason` 折叠区。
- 云函数：无改动（`toolTrace` 已随回包返回）。
- 自测：`parseTrace` 留一个 node 自检（喂几组真实 trace 断言输出），随文件走。

### 边界情况
- 识图（`askImage`）同链路，trace 照常解析。
- 失败回包（nokey/ratelimit/model）没有 trace，不渲染步骤。
- trace 里出现映射表外的新工具名 → 兜底文案「查了一下资料」，不崩不裸奔英文。

### 验收标准
1. 问「这季花了多少」→ 回复里展开可见「叫来记账参谋 → 翻了账本」。
2. 问「后天能打药吗」→ 可见「叫来农事参谋 → 看了天气 → 核对了打药安全」。
3. 闲聊「你好」→ 不出现步骤区。
4. 步骤区展开/收起状态不写入历史，重进不残留。

### 工作量
约 0.5 天，纯前端 + 一个自检脚本。

## 方案三：角色与话术规范（评审 checklist + system prompt 增补）

### 目标
把 Ant X 的 Role / Conversation 设计规范落成两份可用的东西：(1) 参谋角色定义与话术规则，写进云函数 system prompt；(2) 一份 10 条评审 checklist，以后任何涉及对话文案/提示词/卡片的改动都过一遍。

### 角色定义（写进 orchPrompt）
参谋是"村里懂技术、管过账的老把式"：
- 说人话，农户怎么说就跟着怎么说（"打药""上肥"，不说"植保作业""追肥操作"）。
- 先给结论再给依据；不确定就说不确定，不编。
- 不端着、不客气话连篇；一句能说清不说两句。
- 数字带单位，日期说"明天/后天（10月8日）"这种农户口径。

### orchPrompt 增补文案（建议 patch）
在现有 orchPrompt 末尾追加：

```
【说话规矩】
1. 你是"参谋"，不是"AI/智能体/模型"，自称和解释时都不出现这些词。
2. 用农户的话：打药、上肥、浇地、卖粮；禁用术语：上下文、工具调用、起草、落库、确认卡（对农户说"先给你拟好，你点头才记上"）。
3. 拿不准就说拿不准，给出一个能核实的办法（比如"去地里看一眼"）。
4. 数字带单位，钱说"块"也说"元"但同一轮只用一种。
5. 解释"参谋干了什么"时，只说查了什么、拟了什么，不提子代理分工。
```

expertPrompt 不动（子代理输出是给总管看的中间层，术语无妨）。

### 评审 checklist（10 条）
新对话文案 / 提示词 / 卡片模板合入前逐条过：

1. 全文搜不到"智能体、子代理、模型、上下文、落库、草稿（名词）、token、prompt"。
2. 失败话术是"参谋暂时连不上"这一族，不暴露技术原因（ upstream / timeout / 500 ）。
3. 涉及钱的句子：金额、单位、方向（进/出）三者齐全。
4. 涉及日期的句子：相对日 + 绝对日至少其一，且不跨时区歧义。
5. 确认卡标题能让农户不看点开的详情就知道要确认什么。
6. 删除/作废类话术都说清"不能恢复"或"回收站 30 天"。
7. 同一轮回复里人称一致（对农户永远"你"，不混用"您"）。
8. 建议类输出给了依据来源（天气/资料/你的账本），不空口下结论。
9. 长度：单条回复说人话读一遍不超过 20 秒（约 120 字内为宜，超了拆条）。
10. 新增提示文案都在真机上过一遍语音输入场景（说的是否和写的一致）。

### 改动点
- `cloudfunctions/advisorAgent/index.js`：orchPrompt 追加上述"说话规矩"段（约 10 行）。改完需重新部署云函数。
- 本文档即 checklist 落点，后续改动在提交说明里引用本小节。
- 前端既有文案抽查一遍（mine 页模型名、失败 toast 等），不合规的随下次版本顺手改，不单独发版。

### 验收标准
1. 部署后问三个典型问题（该干啥/花多少/能打药吗），回复无禁用词。
2. 故意断网问一句，失败话术符合第 2 条。
3. checklist 在 docs 可查，后续两次文案改动确实过了 checklist（可追溯）。

### 工作量
prompt 增补 0.5 小时 + 部署验证；前端文案抽查约 1 小时。checklist 无额外成本。

---

## 实施顺序建议

1. **方案一（提示集）**：收益最大、零风险、纯前端，先做。
2. **方案二（步骤化）**：同批做，都是 chat 页改动，一次验证。
3. **方案三（话术规范）**：涉及云函数重新部署，单独一个提交，部署后按验收标准抽查。

三个方案合计约 1.5 人日，彼此无依赖，可拆可合。
