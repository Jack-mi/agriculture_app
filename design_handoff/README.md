# Handoff：谷雨记 · 种粮大户农田电子账本（微信小程序）

## Overview
「谷雨记」是给种小麦、玉米的农户和种粮大户用的微信小程序，用来替代纸质账本。数据按「地块 × 作物 × 种植季」组织，每一季从播种日开始、到收获日结束，可以跨年。主要功能：
- **记账**：记录 5 类成本投入，自动分类汇总，并算出全季合计。
- **记事**：记录每天的田间操作、施肥量（斤/亩）和土壤墒情；每天的平均气温和降雨量通过 Open-Meteo 按地块经纬度自动获取，用户可以手工修正。
- **统计**：积温（逐日平均气温的累计和）、降雨累计，收获时输出全周期汇总，并计算亩产和每斤粮成本。
- **离线优先**：数据先写进手机本地，可选开启微信云开发，联网后自动备份。

## About the Design Files
本包里有两部分：
1. `miniprogram/`：**原生微信小程序源码**（WXML/WXSS/JS），可以直接导入微信开发者工具运行。这是最接近生产代码的版本，后续可以在它的基础上继续开发。
2. `prototype/`：**用 HTML 做的设计参考**，是可交互原型，用 React 和浏览器 localStorage 实现，展示预期的界面和行为，**不是生产代码**。它的业务逻辑（`proto/logic.js`）和小程序 `utils/` 的逻辑结构一致。

如果目标技术栈不是原生小程序（例如 Taro、uni-app 或 React Native），请按原型和本文档**在目标框架里重新实现**，数据模型和统计口径保持一致。

## Fidelity
**高保真（hi-fi）**：颜色、字号、间距、交互和文案都已确定。原型用 px 标注，小程序用 rpx，换算关系是 **1px = 2rpx**。

> ⚠️ 设计系统说明：这个项目使用的是自己的「谷雨记」田园视觉：麦绿、麦金、纸色底、大字号、高对比，适合中老年用户在户外使用。当前工作区关联的「玄枢」八字命理设计系统（深色、暗金、神秘风）是另一个产品的，和本产品的定位与用户群体不符，**这次没有套用**。如果确实要换成玄枢风格，需要单独做一轮视觉改版。

## Screens / Views
全局结构：绿色导航栏 `#2E5B34`（白字），底部 TabBar 有 3 个页签：今天 / 地块 / 我的。表单页的主按钮固定在底部栏，按钮高 54px（108rpx）。

### 1. 今天（pages/index）
- **用途**：每天打开的首页，一眼看到每块在种的地，两步之内开始记录。
- **布局**：顶部是绿色 Hero（日期 28px/800 衬线字 + 星期 + 副标题「今天地里干了啥、花了多少，随手记一笔」），Hero 底部留出 46px。下面的卡片区上移 30px，压在 Hero 上。
- **季卡片**（每个在种的季一张）：
  - 顶部：作物徽章（44px、圆角 11px）+ 地块名（20px/800）+ 作物标签，第二行显示「X 亩 · 播种第 N 天」，右侧是箭头 ›。点击进入季详情。
  - 天气四格：今日均温（`#C4532B`）、今日降雨（`#2F6F9F`）、累计积温、累计降雨。背景 `#FBF8EF`，每格之间用 1px 线分隔，数值 19px/800。
  - 「本季已投入 ¥X · ¥Y/亩」，金额 22px/800。
  - 当天已有记录时，显示绿底提示「✓ 今天已记：…」。
  - 两个大按钮：**记一笔账**（麦金 `#C98B1E`）、**记今天的活**（绿色）。
- **空状态**：没有地块时显示「先添加第一块地」；有地块但没有在种的季时显示「还没有在种的作物」和「开始新一季」按钮。
- 页面下拉可以刷新天气；无网络时 Hero 里显示「当前无网络 · 记录已存手机，联网后自动同步」。

### 2. 地块（pages/plots）
- 顶部汇总「N 块地 · 共 X 亩」，右侧有「＋ 添加」按钮。
- 每块地一张卡片：地块名（20px/800），下一行是亩数和位置；没有定位时提示「未定位（无法自动获取天气）」。
- 有在种的季时显示入口条（作物、第几天、投入、积温、降雨）；没有时显示描边按钮「＋ 在这块地开始新一季」。
- 往季记录：虚线分隔，每行显示「年份 作物 ¥成本 · 积温 · 产量」。

### 3. 添加 / 编辑地块（pages/plot-edit）
- 字段：地块名称（必填，最多 20 字）、面积（必填，单位「亩」）、地块位置（调 `wx.chooseLocation` 地图选点，显示北纬和东经）。另有「我就在地头，用当前位置」按钮（调 `wx.getLocation`，gcj02 坐标系）。
- 编辑时底部有「删除这块地」，会级联删除这块地下的季、账目、记事和天气数据，删除前要二次确认。

### 4. 开始新一季（pages/season-new）
- 选地块：用胶囊选择，在种的地块标「（在种）」。一块地同一时间只能有一个在种的季，重复开季会弹窗阻止。
- 选作物：三列方块，小麦、玉米可选；花生置灰，提示「后续开放」。**默认作物按月份猜**：5–7 月默认玉米，其他月份默认小麦。
- 播种日期（不能晚于今天）、播种量（斤/亩）、整地情况（快捷词：旋耕 / 深翻 / 深松 / 免耕 / 秸秆还田，点一下追加到文本 + 多行输入框）。
- 保存后跳转到季详情，并在后台补齐天气数据。

### 5. 季详情（pages/season）
- **顶部**：绿底，作物徽章 + 「2026–2027 小麦」（冬小麦跨年时这样显示）+ 状态标签（在种为麦金底；已收获为半透明）。下方 KPI 三格：总投入（附 ¥/亩）、累计积温（℃·天）、累计降雨（毫米）。
- **Tab**（吸顶，高 48px，选中项绿色加粗并带 3px 下划线）：账本 / 记事 / 天气 / 信息。
  - **账本**：顶部是 10px 高的分类占比条；下面列出 5 类，每行是色点 + 类名 + 笔数 + 金额 + 百分比，点击展开细分类汇总；最后是「本季合计」。再下面是流水列表：日期 | 分类标签 + 细分类 + 备注 | 金额，点击进入编辑。
  - **记事**：按日期倒序分组。组头是「9月28日 周一 · 第N天」，右侧显示当天的「℃ · mm」。每条记事显示操作类型（绿色粗体）、正文、施肥明细、墒情、关联花费（麦金色）。
  - **天气**：全周期积温（大号数字，`#C4532B`）和全周期降雨（大号数字，`#2F6F9F`）；数据完整度（共 N 天、已获取、手工修正、缺失）；近 30 天降雨柱状图；「重新获取天气」按钮。下面是逐日表格：日期 | 均温 | 降雨 | 累计积温 | 累计降雨，手工修正过的日期标「改」。点某一行会弹出底部弹层，可修正均温和降雨，也可以「恢复自动」。
  - **信息**：播种时间、播种量、整地情况。已收获时还显示收获时间、产量、亩产、每斤成本、全周期积温和降雨，以及「修改收获信息」「撤销收获」两个按钮。底部是「删除这一季」。
- **底部栏**：在种时是「记一笔账 / 记今天的活 / 收获」（收获按钮宽 76px）；已收获时是「补记一笔账 / 补记事」。

### 6. 记一笔账（pages/cost-edit）
- 5 类用三列方块选择（带色点），下面用胶囊选细分类。
- 雇工类额外显示「雇了几个人」×「每人每天」，金额自动计算。
- 金额输入：¥ 符号 28px 麦金色，数字 36px/800，下方 2px 麦金色底线；新建时自动聚焦。
- 日期（不能晚于今天）、备注（最多 60 字；占位提示随类别变化）。
- 底部栏：「保存，再记一笔」（连续录入时清空金额和备注）+「保存」。

### 7. 记今天的活（pages/log-edit）
- 右上角是日期胶囊（默认显示「今天」），下面一条显示当天天气。
- 操作类型可多选（施肥 / 打药 / 浇水 / 机械作业 / 除草 / 巡田 / 其他）。选了「施肥」时展开施肥明细：品类 + 用量（斤/亩）。
- 具体情况：多行文本。提示用户「用了什么机械、谁家的机械也写这里」，PRD 确认作业机械不单设字段。
- 土壤墒情：快捷选项（干旱 / 偏干 / 适宜 / 偏湿 / 积水）+ 自由文本。
- 底部栏：**保存并记花费**：保存记事后跳转到记账页，按操作类型预设类别（施肥→农资/化肥，打药→农资/农药，机械作业→机械，浇水、除草→雇工），备注预填，并把 `logId` 关联到这条记事。另一个按钮是「保存」。
- 校验：至少选一项操作，或写正文，或填墒情。

### 8. 登记收获（pages/harvest）
- 收获日期（不早于播种日、不晚于今天）、总产量（斤，实时显示折合亩产）、备注。
- 全周期汇总是两列网格：生长天数、积温总和、降雨总量、总投入、每斤粮成本。
- 确认后弹窗显示「这一季收官了」和汇总数据，然后返回。

### 9. 我的（pages/mine）
- 头像块（绿底白字「谷」）+ 「我的农田账本」+ 当年已投入。
- 四格计数：地块、种植季、笔账、条记事。

## Interactions & Behavior
- 页面切换在原型里是 220ms 淡入；小程序用原生转场。弹层遮罩淡入，底部弹层从下往上滑入（250ms）。
- 按钮按下时透明度降到 0.8（`hover-class="btn-hover"`）。
- Toast：1.5 秒，保存成功提示「记好了」或「已保存」。
- 危险操作（删除地块、删除季、删除账目、删除记事）都要弹 Modal 二次确认，确认按钮用 `#B3372B`。
- 数字统一用等宽数字（`font-variant-numeric: tabular-nums`）；金额加千分位，整数不显示小数。

## State Management / Data
数据存在本地（Storage key `guyuji_db_v1`），结构如下：
```
plots:   { id, name, area(亩), lat, lng, address, createdAt }
seasons: { id, plotId, crop('wheat'|'corn'), sowDate, seedRate(斤/亩), tillage,
           status('growing'|'done'), harvestDate, yieldJin, harvestNote }
costs:   { id, seasonId, date, cat('agri'|'mach'|'trans'|'labor'|'asset'), sub, amount,
           people, unitPrice, note, logId }
logs:    { id, seasonId, date, ops[], text, fertName, fertRate, moisture }
weather: { [plotId]: { [YYYY-MM-DD]: { t(℃), p(mm), src('api'|'manual') } } }
```
- **天气获取**（`utils/weather.js`）：只请求缺失的日期，昨天和今天的数据每次都重新拉。近 30 天用 `api.open-meteo.com/v1/forecast`（参数 `past_days=31`），更早的日期用 `archive-api.open-meteo.com/v1/archive`。字段是 `temperature_2m_mean` 和 `precipitation_sum`，时区 `Asia/Shanghai`。**手工修正的日期永远不会被接口数据覆盖。**
- **统计口径**：积温 = Σ 每日平均气温（包含负值，同时展示只算 0℃ 以上的值）；固定资产计入当季总成本；在种的季统计到今天，已收获的季统计到收获日。
- **云同步**（`utils/sync.js`，可选）：填写 `CLOUD_ENV` 后生效。每个用户在集合 `guyuji_userdata` 里存一条文档（整份 JSON），数据写入后节流 3 秒同步，网络恢复时补推。新设备本地没有数据时，从云端拉取恢复。

## Assets
- `miniprogram/assets/crops/wheat.svg`、`corn.svg`、`peanut.svg`：作物图标（彩色扁平 SVG，48×48 viewBox）。**还没接入页面**，目前页面上的作物徽章仍是汉字「麦 / 玉 / 花」。接入方式：`<image src="/assets/crops/{{crop}}.svg" />` 替换 `.crop` 里的文字；原型里的对应文件是 `proto/crops.js`（`window.CROP_SVG`）。
